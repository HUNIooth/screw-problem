# Problem Discovery

목표: **이 대화를 읽지 않은 에이전트가 인계 문서만 보고 바로 일을 시작하고, 끝났는지 스스로 판정할 수 있게** 만든다.

모호한 문제에서 가장 비싼 실수는 잘못된 문제를 푸는 것이다. 문서를 원했는데 앱을 만들거나, 원본이 아닌 사본으로 작업하는 식이다. 실행 전에 조금 더 찾고 묻는 편이 다시 만드는 것보다 싸다.

이 스킬은 **실행하지 않는다.** 인계 문서와 준비 판정에서 멈춘다. 사용자가 "진행해"라고 하면 그때 HANDOFF.md대로 시작한다.

## 0. 규모 정하기

시작할 때 한 줄로 알리고 진행한다.

- **경량**: 반나절 안쪽, 산출물 하나, 결정권자 한 명. `HANDOFF.md` 하나에 요구사항과 계획을 섹션으로 넣는다.
- **표준**: 그보다 크거나 여러 에이전트가 나눠 맡을 일. 네 파일을 모두 쓴다.

## 1. 먼저 찾기

사용자에게 묻기 전에 직접 찾는다. 사용자에게 물을 것은 **사용자만 아는 것(의도, 결정, 선호)** 이고, 사실 확인은 내 몫이다.

- 볼 곳: 작업 폴더의 기존 파일, `AGENTS.md`, README, 작업 기록, 설계 문서, 원천 자료(업무 규정 문서, 데이터 샘플, 이전 산출물), 필요하면 웹.
- 폴더가 크고 하위 에이전트를 쓸 수 있으면 "무엇이 어디 있는지"만 맡기고 결론만 받는다.
- 결과를 **지식 장부** 표로 정리해 대화에 보여 준다.

| 구분 | 내용 | 근거 | 영향 |
|---|---|---|---|
| 사실 | 확인된 것 | 파일:줄, URL, 사용자 발언 | - |
| 모름 | 아직 모르는 것 | - | 높음/중간/낮음 |
| 추정 | 그럴 것 같지만 확인 안 된 것 | 추정 이유 | 높음/중간/낮음 |

근거를 댈 수 없으면 사실 칸에 넣지 않는다. 추정을 사실처럼 적는 것이 이 단계에서 가장 흔하고 해로운 실수다.

## 2. 빈틈 순위

'모름'과 '추정' 항목마다 두 가지를 본다.

- **영향**: 틀리면 결과물이 뒤집힌다(높음), 일부 고친다(중간), 사소하다(낮음)
- **푸는 방법**: 조사하면 풀림, 사용자만 앎, 해 봐야 앎

처리:
- 조사로 풀리는 것: 묻지 말고 조사한다.
- 사용자만 알고 영향이 높은 것: 3단계 질문의 최우선.
- 해 봐야 아는 것: 계획의 첫 단계(시험 작업)로 보낸다.
- 영향이 낮은 것: 기본값을 정하고 '추정'으로 남긴다. 묻지 않는다.

아래 여섯 가지는 빠지면 반드시 구멍이 나므로 장부에 하나씩은 있어야 한다.

1. **목적과 성공 기준**: 왜 하나, 끝났다는 걸 무엇으로 아나
2. **산출물 형태**: 문서, 앱, 데이터, 영상, 결정 중 무엇이고 누가 쓰나. "~하는 흐름으로"는 제작 과정 문서 요청일 수 있다.
3. **입력과 원천**: 자료가 어디 있고 믿을 만한가, 원본인가 사본인가
4. **제약**: 기한, 비용(토큰 포함), 보안, 권한, 금지 사항, 써야 하는 도구
5. **경계와 예외**: 범위 밖인 것, 예외 상황, 실패하면 어떻게 하나
6. **결정과 검토**: 누가 정하고 누가 검토하나, 결과물을 누가 받나

문제 유형별 추가 질문은 [references/question-bank.md](references/question-bank.md)에서 해당 유형만 골라 읽는다.

## 3. 질문하기

지금 답할 수 있는 질문(앞선 결정이 이미 정해진 것)만 한 라운드로 묶는다. 다른 질문의 답에 따라 달라지는 질문은 다음 라운드로 미룬다.

형식:

```
Q1. <질문 제목>
왜: <틀리면 무엇이 뒤집히는지 한 줄>
  A. <선택지>: <고르면 어떻게 되나>
  B. <선택지>: <고르면 어떻게 되나>
  C. <선택지>: <고르면 어떻게 되나>
  D. 직접 입력
추천: A (<이유>)
```

- **결정 질문은 선택지를 3개 이상** 주고 하나를 추천한다. 사용자가 "Q1 A, Q2 C"처럼 짧게 답할 수 있고, 생각 못 한 길도 보여 줄 수 있다.
- 선택지는 실제로 다른 결과를 내는 것만 넣는다. 진짜 선택지가 2개뿐이면 2개로 둔다. 개수를 채우려고 억지 선택지를 만들지 않는다.
- 항상 '직접 입력'을 둔다. 선택지 밖에 정답이 있을 수 있다.
- **사실 질문(날짜, 경로, 건수, 이름)은 선택지 없이** 열어서 묻고 답 예시를 단다. 사실을 선택지로 지어내면 그중 하나가 골라져 틀린 사실이 들어온다.
- 한 라운드 최대 5개, 영향 높은 것부터.
- 질문을 보냈으면 **턴을 끝내고 답을 기다린다.** 답을 받지 않은 채 추천 답으로 계속 진행하지 않는다.
- 사용자가 "알아서 해"라고 하면 추천 답을 채택하고 '추정(사용자 위임)'으로 기록한다.
- 비대화 실행(`codex exec` 등)이라 물을 수 없으면 추천 답을 모두 '추정'으로 기록하고 준비 판정을 🟡 이하로 둔다.
- 라운드가 끝나면 장부를 갱신하고, 새로 열린 질문만 다음 라운드로 보낸다.
- 세 라운드가 넘어가면 멈추고, 남은 것은 기본값과 추정으로 처리할지 묻는다.

## 4. 요구사항으로 바꾸기

- 항목마다 `R-01` 번호, 내용, **검증 방법**(통과를 어떻게 판정하나), 근거(장부 항목), 필수/희망.
- 검증할 수 없는 말은 바꾼다. "빠르게"는 "10초 안에"로, "깔끔하게"는 기준 문서나 예시 지정으로.
- **범위 밖**을 따로 적는다. 수행 에이전트가 선의로 일을 키우는 걸 막는 가장 싼 방법이다.

## 5. 대안과 계획

- 방법이 여럿이면 2~3개를 장단점, 위험, 비용으로 비교하고 하나를 추천한다. 사실상 하나뿐이면 생략.
- 단계마다 입력, 산출물, 검증 기준, 선행 단계를 적는다.
- 영향 높은 '해 봐야 아는 것'은 맨 앞 시험 단계로 두고, 실패하면 계획을 다시 짜는 분기점도 적는다.
- 동시에 돌릴 수 있는 단계를 표시한다. 여러 에이전트로 나눌 때 쓴다.

## 6. 준비 판정

- [ ] 영향 높은 '모름'이 남아 있지 않다 (시험 단계로 보낸 것은 제외)
- [ ] 필수 요구사항마다 검증 방법이 있다
- [ ] 산출물 형태와 저장 위치가 정해졌다
- [ ] 완료 조건을 제3자가 판정할 수 있다
- [ ] 권한과 금지 사항이 적혀 있다

판정:
- 🟢 **실행 가능**
- 🟡 **조건부**: 남은 추정 목록을 사용자가 승인하면 실행 가능
- 🔴 **추가 탐색 필요**: 무엇을 더 알아야 하는지 적고 1~3단계로 돌아간다. 사용자가 그래도 진행하겠다면 위험을 HANDOFF.md 맨 위에 적고 문서를 만든다.

## 7. 인계 문서

**위치**: 작업 폴더 아래 `discovery/<YYYYMMDD>_<주제>/`. 어느 폴더인지 불분명하면 묻는다. 기존 `AGENTS.md`, `CLAUDE.md`는 덮어쓰지 않는다. 작업 폴더 루트의 `AGENTS.md`는 이후 모든 Codex 세션이 자동으로 읽으므로, 인계용 `AGENTS.md`는 반드시 이 하위 폴더에 둔다. 수행 에이전트는 이 폴더에서 시작하면 지침을 자동으로 받는다.

**템플릿**: [references/templates.md](references/templates.md)

| 파일 | 담는 것 | 성격 |
|---|---|---|
| REQUIREMENTS.md | 무엇을, 왜, 성공 기준, 범위 밖 | 합의된 내용 |
| PLAN.md | 순서와 각 단계의 검증 | 방법 |
| AGENTS.md | 수행 에이전트의 역할, 권한, 금지, 입출력, 일하는 방식 | 잘 안 바뀜 |
| HANDOFF.md | 지금 상태, 다음 행동, 남은 추정, 읽는 순서 | 계속 바뀜 |

쓰고 나서 **자기 완결 점검**: "이 대화를 못 본 에이전트가 HANDOFF.md부터 열어 첫 작업을 시작할 수 있나?"
- 대화에서만 나온 용어, 약어, 별명은 정의를 붙이거나 풀어 쓴다.
- 경로는 절대경로로 쓴다.
- "앞에서 말한", "그 파일" 같은 대화 의존 표현을 없앤다.
- 사용자가 내린 결정은 이유와 함께 적는다. 이유가 없으면 수행 에이전트가 같은 질문을 다시 꺼낸다.

중요한 인계라면 하위 에이전트에게 HANDOFF.md 경로만 주고 "첫 작업과 모르는 점을 말하라"고 시험할 수 있다. 토큰이 드니 사용자가 원할 때만 한다.

문서는 개조식과 표로 쓰고 표지, 배지, 장식은 넣지 않는다. 같은 내용을 제목, 요약, 본문에서 되풀이하지 않는다.

## 8. 보고

대화에 짧게 남긴다.

- 만든 파일 경로
- 준비 판정(🟢/🟡/🔴)과 이유 한 줄
- 승인이 필요한 추정 상위 3개
- 다음 행동: 누가(사용자, 이 세션, 다른 에이전트) 무엇을

마지막 줄은 상태줄(✅ 완료 / ⏳ 진행 중 / 🛑 결정 필요)로 끝낸다.

## 하지 말 것

- 탐색 중에 산출물을 만들기 시작하기
- 조사하면 알 수 있는 걸 사용자에게 묻기
- 추정을 사실 칸에 적기
- 질문을 보내 놓고 답을 기다리지 않고 진행하기
- 인계 문서에 대화 맥락에 기대는 표현 남기기
