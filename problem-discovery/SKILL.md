# Problem Discovery

목표: 잘못된 문제를 풀지 않도록 짧게 조사하고 물은 뒤, 다른 에이전트가 문서만 보고 바로 구현할 수 있게 넘긴다.

## 시작

- `~/.screw-problem/설정.md`를 읽는다. 없을 때는 screw-setup의 규칙을 따른다.
- `사용자_검토.md`에 '작업 설정'이 없으면 먼저 두 가지만 묻는다: 내 문제인지 현업 요건 구현인지(결정권자 포함), 이번 제약. drill-pilot이 남긴 답은 다시 묻지 않는다.
- 규모를 한 줄로 알린다. 경량(반나절, 산출물 하나)은 `HANDOFF.md` 한 장, 표준은 문서 다섯 개.

## 1. 찾기

묻기 전에 작업 폴더, README, 기존 문서, 원천 자료, 필요하면 웹을 본다. 결과는 장부로 보여 준다.

| 구분 | 내용 | 근거 | 영향 |
|---|---|---|---|
| 사실 / 모름 / 추정 | | 파일:줄, URL, 발언 | 높음 / 중간 / 낮음 |

- 근거가 없으면 사실 칸에 쓰지 않는다.
- 꼭 확인할 여섯 가지: 목적과 성공 기준, 산출물 형태와 누가 어디서 돌리나, 입력과 원천(원본인가), 제약(기한, 비용, 보안, 권한, 금지), 범위 밖과 예외, 누가 정하고 누가 받나.

## 2. 묻기

- 조사로 풀리는 건 조사한다. 영향 낮은 건 기본값을 정해 '추정'으로 둔다. 해 봐야 아는 건 계획의 0단계 시험으로 보낸다.
- 사용자만 알고 영향이 큰 것만 묻는다. 한 라운드 최대 3개.

```
Q1. <질문>
왜: <틀리면 무엇이 뒤집히나>
  A. <선택지>: <고르면 어떻게 되나>
  B. <선택지>: <고르면 어떻게 되나>
  C. 직접 입력
추천: A (<이유>)
```

- 사실 질문(날짜, 경로, 건수)은 선택지 없이 열어서 묻는다.
- 보냈으면 턴을 끝내고 기다린다. "알아서 해"면 추천을 '추정(위임)'으로 채택한다. 물을 수 없는 실행이면 추천을 추정으로 두고 판정을 🟡 이하로.
- 세 라운드 뒤에는 더 묻지 않고 계획으로 간다.

## 3. 요구사항과 계획

- 요구사항: `R-01` 번호, 내용, 검증 방법, 근거. 검증 못 하는 말은 바꾼다("빠르게"는 "10초 안에"). 범위 밖을 적는다.
- 방법이 여럿이면 2~3개를 비교하고 하나를 추천한다.
- 메이저 기능(사용자가 얻는 것)과 마이너 작업(한 가지 일, 테스트로 판정)으로 나눈다. 마이너마다 통과 기준(테스트)과 선행 작업.
- 커밋 분기점은 검토하기 좋은 변경 단위로 정한다. 횟수를 강제하지 않는다.
- 위험한 모름은 0단계 시험으로 두고, 실패하면 다시 짜는 분기점을 적는다. 동시에 돌릴 수 있는 작업을 표시한다.

## 4. 판정

- 🟢 실행 가능 / 🟡 남은 추정을 사용자가 승인하면 실행 / 🔴 더 알아야 함(무엇을)
- 기준: 영향 큰 모름이 없다, 필수 요구사항마다 검증 방법이 있다, 산출물과 위치, 권한과 금지가 정해졌다, 마이너마다 테스트가 있다.
- 실행 요청이 이미 있으면 🟢이거나 🟡 승인 뒤 바로 구현한다. 🔴이면 멈추고 부족한 것을 알린다.

## 5. 문서

위치는 사용자가 정한 곳, 없으면 `discovery/<YYYYMMDD>_<주제>/`. 양식은 [references/templates.md](references/templates.md). 점검표 [references/review/](references/review/) 세 개를 인계 폴더 `review/`로 복사한다. 작업 폴더 루트의 기존 AGENTS.md는 덮어쓰지 않는다.

| 파일 | 담는 것 |
|---|---|
| 사용자_검토.md | 사람이 보는 유일한 문서. 지금 상태, 정할 것 최대 3개, 확인 지점, 피드백 |
| REQUIREMENTS.md | 목적, 요구사항과 검증, 범위 밖, 장부 |
| PLAN.md | 메이저와 마이너, 커밋 분기점 |
| AGENTS.md | 수행 에이전트 규칙. 수행 에이전트는 스킬 없이 이것만 보고 일한다 |
| HANDOFF.md | 지금 상태, 다음 행동, 남은 추정, 읽는 순서 |

쓰는 법:
- 짧게. 개조식, 한 항목 한 줄. 같은 내용을 여러 문서에 되풀이하지 않고 링크한다. 사람이 한 번에 못 읽을 만큼 길어지면 줄인다.
- 대화를 못 본 에이전트가 HANDOFF.md부터 열어 첫 작업을 시작할 수 있어야 한다. 절대경로, 대화에서만 쓴 말은 풀기, 결정에는 이유 한 줄.
- 사용자가 사용자_검토.md만 보고 다음 지시를 내릴 수 있어야 한다.
- 설정이 하위 에이전트를 허용하면, 중요한 인계는 하위 에이전트에게 HANDOFF.md 경로만 주고 첫 작업과 모르는 점을 말하게 해 시험할 수 있다.

## 6. 피드백

- 사용자 원문은 보존하고 해석과 반영은 따로 적는다.
- 목적과 범위는 REQUIREMENTS, 방법은 PLAN, 계속 적용될 규칙은 AGENTS, 상태는 HANDOFF에 반영한다. 영향 없는 문서는 건드리지 않는다.
- 쓰기 직전에 다시 읽어 새 피드백을 덮지 않는다. 빈 답은 동의가 아니다.

## 7. 보고

파일 경로, 판정과 이유 한 줄, 승인할 추정 상위 3개, 다음 행동(새 세션이면 프로젝트 루트에서 `<HANDOFF.md 절대경로> 읽고 시작해`). 마지막 줄은 상태줄(✅ 완료 / ⏳ 진행 중 / 🛑 결정 필요).
