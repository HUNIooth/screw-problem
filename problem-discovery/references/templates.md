## AGENTS.md

```markdown
# <주제> 수행 지침

## 역할
<무엇을 하는> 에이전트. 목표: REQUIREMENTS.md 필수 요구사항 전부 통과.

## 읽는 순서
HANDOFF.md → 사용자_검토.md → REQUIREMENTS.md → PLAN.md

## 권한과 금지
- 읽기 / 쓰기 / 실행: <절대경로, 명령>
- 금지: <원본, 과금 API, 확인 없는 삭제, 외부 전송, 배포, 공통 제약>

## 일하는 방식
- 승인된 범위는 멈추지 않고 구현한다. 마이너마다 실패하는 테스트를 먼저 보고, 통과할 만큼 구현하고, 통과를 확인한다.
- 멈추는 곳은 둘이다.
  1. 커밋 분기점: review/ 점검표로 변경분 검토 → 사용자_검토.md에 무엇을 어떻게 짰는지, 검토 결과, 볼 것, 질문, 커밋 메시지 초안 → 컨펌 뒤 커밋. 메시지에 분기점 번호와 R 번호.
  2. 기존 지시와 우선순위로 풀 수 없는 모호함이나 충돌: 그 부분만 멈추고 묻는다. 답과 무관한 작업은 계속한다.
- 구현이 명확한 요구를 어겼으면 묻지 않고 고치고 검증한다.
- 한 번에 보내는 질문은 설계 선택과 놓쳤을 수 있는 것(설명과 다른 데이터, 규칙 없는 예외, 개인정보, 비용)을 합쳐 최대 3개. 결정 질문은 선택지 3개 이상과 추천, 사실 질문은 열어서. 넘치면 HANDOFF.md '열린 질문'. 조사로 알 수 있는 건 묻지 않는다.
- 사용자 답 중 계속 적용될 것은 아래 '사용자 기준'에 원문과 함께 추가하고 사용자_검토.md에 알린다.
- 버그는 재현하고 원인을 확인한 뒤 고친다. 같은 문제에서 두 번 실패하면 멈추고 올린다.
- 완료는 실제 실행 결과를 붙여서만 말한다. 돌리지 않은 건 '미실행'.
- 요구사항에 없는 기능은 더하지 않는다. 필요해 보이면 질문으로.
- 마이너마다 다섯 줄 점검: 함수 하나는 한 가지 일 / 입출력, 업무 규칙, 저장을 섞지 않음 / 의존은 바깥에서 업무 규칙 쪽으로 / 비밀값은 코드 밖, 입력 검증, 쿼리는 매개변수 / 같은 코드 세 번 복사 금지.
- 보안 치명 항목이 있으면 커밋하지 않는다. 린터, 스캐너가 있으면 먼저 돌린다.
- git 저장소가 아니면 첫 커밋 분기점에서 만들지 묻는다.
- 문서와 기록은 짧게: 개조식, 한 항목 한 줄, 되풀이 금지.

## 사용자 기준
| 원문 | 규칙 | 날짜 |

## 완료 조건
- [ ] 필수 요구사항 전부 통과, 실행 증거 있음
- [ ] 산출물이 정해진 위치에 있음
- [ ] HANDOFF.md에 최종 상태와 남은 일
```
