# 인계 문서 템플릿

표준 모드는 아래 인계 문서 4종과 [사용자_검토.md 양식](user-review.md)을 쓴다. 경량 모드는 `HANDOFF.md(경량)`에 사용자 판단과 피드백 안내를 함께 넣는다.
빈 섹션은 "해당 없음"으로 적고 지우지 않는다. 비어 있는 이유가 정보다.

## AGENTS.md

수행 에이전트가 작업 내내 따르는 지침. 진행 상태는 여기 쓰지 않는다(HANDOFF.md에).

```markdown
# <주제> 수행 지침

## 역할
- 너는 <무엇을 하는> 에이전트다. 목표는 REQUIREMENTS.md의 필수 요구사항을 모두 통과시키는 것이다.

## 읽는 순서
1. HANDOFF.md (현재 상태와 다음 행동)
2. 사용자_검토.md (새 피드백과 사용자 판단)
3. REQUIREMENTS.md
4. PLAN.md

## 권한
- 읽어도 되는 곳: <절대경로>
- 써도 되는 곳: <절대경로>
- 실행해도 되는 것: <명령/도구>

## 금지
- <건드리면 안 되는 파일/원본>
- <호출하면 안 되는 서비스/과금 API>
- <사용자 확인 없이 하면 안 되는 일: 삭제, 외부 전송, 배포 등>

## 입력과 출력
| 구분 | 내용 | 위치 | 형식 |
|---|---|---|---|
| 입력 | | | |
| 출력 | | | |

## 일하는 방식
- 시작할 때와 사용자 검토 시점에 사용자_검토.md의 새 피드백을 확인한다. 사용자가 다른 문서 위치를 지정했다면 그 위치를 따른다.
- 사용자 원문, 담당자 발언, 에이전트 해석/추천을 구분한다. 사용자 직접 작성 부분을 고쳐 쓰지 않는다. 갱신 직전에 최신 파일을 다시 읽고 프로젝트의 판 관리 규칙을 따른다.
- 현재 권한 안의 명확한 수정은 수행한다. 이미 받은 허락을 다시 묻지 않으며, 빈 피드백을 동의로 취급하지 않는다.
- 중요한 해석이 갈리거나 목표/범위/권한이 달라질 때만 필요한 부분을 질문한다. 조사로 확인 가능한 사실은 먼저 확인한다.
- 목적/범위/성공 기준은 REQUIREMENTS, 방법/순서/검증은 PLAN, 지속 규칙은 AGENTS, 상태/다음 행동은 HANDOFF에 반영한다. 영향 없는 문서는 다시 쓰지 않는다.
- 단계가 끝날 때 HANDOFF의 상태와 사용자 검토 문서의 변경 전후, 이유, 검증 증거, 후속 질문을 갱신한다.
- 요구사항과 어긋나는 결정이 필요하면 멈추고 사용자에게 묻는다. 스스로 범위를 넓히지 않는다.
- 추정으로 진행한 것은 HANDOFF.md '남은 추정'에 적는다.
- 기술 검증과 실제 업무 사용자의 수용 여부를 분리한다. 아직 실행하지 않은 검증을 통과로 기록하지 않는다.
- 피드백은 사용자가 반영을 요청하거나 합의한 점검 시점에 읽는다. 파일 저장만으로 자동 반영된다고 안내하지 않는다.

## 완료 조건
- [ ] 필수 요구사항 전부 검증 통과
- [ ] 산출물이 정해진 위치에 있음
- [ ] HANDOFF.md에 최종 상태와 남은 일 기록
- [ ] 사용자가 받을 결과와 확인 방법, 실제 검증 증거, 남은 판단을 알 수 있음
```
