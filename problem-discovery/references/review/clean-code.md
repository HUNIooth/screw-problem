# 클린 코드 점검표

커밋 확인 때 이번 변경분(diff)에만 적용한다. 걸린 항목은 고치고, 못 고치면 이유를 사용자_검토.md에 올린다.

| 점검 | 걸리는 신호 | 고치는 방향 |
|---|---|---|
| 이름 | `data`, `tmp`, `process()`, `flag`처럼 이름만 봐서는 하는 일을 모름 | 하는 일이나 담는 것으로 이름을 바꾼다 |
| 함수 크기 | 한 함수가 화면 한 장(40줄 안팎)을 넘거나, 설명에 "그리고"가 두 번 이상 들어감 | 한 가지 일씩 함수로 나눈다 |
| 중첩 | `if`/`for`가 3단 넘게 겹침 | 조건이 안 맞으면 먼저 빠져나오게(early return) 바꾸거나 함수로 뺀다 |
| 중복 | 같은 코드 조각이 세 군데 이상 | 함수나 상수로 모은다. 두 군데까지는 억지로 묶지 않는다 |
| 숫자와 문자열 | 뜻 모를 숫자, 여러 곳에 흩어진 같은 문자열 | 이름 붙은 상수나 설정으로 뺀다 |
| 오류 처리 | 예외를 삼키는 빈 `except`/`catch`, 실패해도 성공처럼 반환 | 처리할 수 없으면 올려 보내고, 처리하면 기록을 남긴다 |
| 매개변수 | 인자가 4개 넘거나 `True/False` 플래그로 동작이 갈림 | 묶음 객체로 받거나 함수를 둘로 나눈다 |
| 주석 | 코드를 그대로 되읽는 주석, 주석 처리된 옛 코드 | 왜 그렇게 했는지만 남기고 나머지는 지운다 |
| 죽은 코드 | 안 쓰는 함수, import, 변수 | 지운다 |
| 테스트 | 테스트 이름만 보고 무엇을 확인하는지 모름, 한 테스트가 여러 동작을 확인 | 테스트 하나에 동작 하나, 이름에 기대 결과를 쓴다 |

프로젝트에 린터나 포매터가 있으면 먼저 돌리고, 도구가 잡는 항목은 이 표로 다시 보지 않는다.
