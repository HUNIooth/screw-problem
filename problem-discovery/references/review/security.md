# 보안 점검표

커밋 확인 때 이번 변경분에 적용한다. **치명** 항목이 걸리면 커밋하지 않고 먼저 고친다. 고칠 수 없으면 사용자에게 올린다.

| 등급 | 점검 | 걸리는 신호 |
|---|---|---|
| 치명 | 비밀값 | 키, 비밀번호, 토큰, 접속 문자열이 코드나 커밋에 들어감. `.env`가 추적됨 |
| 치명 | 인젝션 | 사용자 입력을 이어 붙인 SQL, 셸 명령, 파일 경로. `eval` 계열 |
| 치명 | 권한 확인 | 로그인이나 권한 확인 없이 남의 데이터를 읽거나 바꿀 수 있는 경로. 확인을 화면에서만 하고 서버에서 안 함 |
| 치명 | 개인정보 | 주민번호, 연락처, 계좌 같은 정보가 로그, 오류 메시지, 테스트 데이터에 그대로 남음 |
| 중요 | 입력 검증 | 외부 입력(요청, 파일, 환경 변수)의 형식, 길이, 범위를 확인하지 않음 |
| 중요 | 오류 노출 | 스택 트레이스, 내부 경로, 쿼리가 사용자 화면에 보임 |
| 중요 | 파일 업로드 | 확장자/크기 제한 없음, 업로드 파일을 실행 가능한 위치에 저장 |
| 중요 | 의존성 | 새로 추가한 패키지의 출처와 알려진 취약점을 확인 안 함 |
| 중요 | 암호화 | 암호화나 해시를 직접 구현함. 비밀번호를 평문이나 빠른 해시로 저장 |
| 참고 | 최소 권한 | DB 계정, API 키, 파일 권한이 필요보다 넓음 |
| 참고 | 웹 기본 | CORS 전체 허용, 쿠키 보안 속성 없음, 상태를 바꾸는 요청에 CSRF 대책 없음 |

프로젝트에 보안 스캐너(예: 의존성 검사, 비밀값 탐지, 정적 분석)가 있으면 먼저 돌리고 결과를 확인 지점에 붙인다. 이 표는 도구가 못 잡는 설계상의 문제를 보는 용도다.
