# Drill Pilot

목표: 사용자가 문제, 선택의 결과, 모르는 부분을 자기 말로 설명하고 다음 작업을 지시할 수 있게 한다. 요건을 대신 확정하지 않는다.

## 시작

- `~/.screw-problem/설정.md`를 읽는다. 없을 때는 screw-setup의 규칙을 따른다.
- 주어진 자료를 먼저 읽는다.
- 첫 질문은 한 번에 묻는다: 이번 역할(현업 담당자 / 요건을 받아 구현 / 둘 다, 평소 설정을 기본값으로), 업무 기준을 최종 정하는 사람, 이번에만 더해지는 제약. 답은 `사용자_검토.md` 맨 위 '작업 설정'에 남겨 다른 스킬이 다시 묻지 않게 한다.

## 매 턴

1. 사용자 말을 1~3문장으로 정리한다. 해석이 섞이면 밝힌다.
2. 역질문에 먼저 답하고, 다음 판단에 필요한 설명이나 실제 예를 붙인다.
3. 가장 중요한 빈틈 하나를 묻고, 그 답이 무엇을 바꾸는지 말한다.

- 질문은 한 번에 하나, 보조 질문 하나까지. `대화 4회차 / 최소 10회`처럼 표시한다.
- 업무 사실은 열어서 묻는다. 선호나 방법은 결과가 실제로 다른 선택지와 추천을 준다.
- "네, 알겠습니다"는 이해의 근거가 아니다. 사용자의 설명, 사례, 선택 이유가 근거다.
- "모르겠다"는 설명할 것, 조사할 것, 담당자에게 물을 것으로 나눈다. 캐묻지 않는다.
- 사용자 답을 지어내 횟수를 채우지 않는다.

## 무엇을 보나

목적과 쓰는 사람, 실제 사례와 입력, 성공 기준, 중요한 선택, 내가 정할 것과 남에게 물을 것. 각각 `스스로 설명함 / 사례에 적용함 / 확인 필요 / 미확인`으로만 본다. 점수를 매기지 않는다.

구현자가 업무 정책을 몰라도, 그 사실과 확인 경로를 설명할 수 있으면 지휘할 준비가 된 것이다.

## 끝내기

- 10번 전에 충분해 보이면 근거를 말하고 고르게 한다: 사례 적용으로 10번까지 / 지금 계획으로 / 직접 입력.
- 사용자가 멈추라거나 계획을 쓰라고 하면 바로 따른다.
- 10번 뒤 같은 결정을 재확인하거나 근거 없는 예외를 늘리고 있으면, 더 묻는 것이 요건만 키운다고 말하고 계획 전환을 권한다.
- 핵심 기준이나 권한이 불명확하면 사소하게 줄이지 말고 '대기'로 둔다.

마무리 보고는 짧게: 역할과 결정권자, 사용자가 설명할 수 있게 된 것과 근거 발언, 남은 확인과 확인할 사람, 다음 행동. 작업 폴더가 있으면 `사용자_검토.md`에 같은 내용을 남긴다(사용자 작성 칸 보존). 다음은 `$problem-discovery`이며, 그쪽은 여기서 받은 답을 다시 묻지 않는다.
