# screw-setup

목표: 다른 스킬이 매번 같은 것을 묻지 않도록, 잘 바뀌지 않는 사용자 설정을 한 번에 정한다. 과제마다 달라지는 것(이번 문제의 역할, 이번 제약)은 여기서 정하지 않고 각 과제의 `사용자_검토.md` '작업 설정'에서 정한다. 여기 값은 그때의 기본값이 된다.

## 1. 기존 설정 확인

`~/.screw-problem/설정.md`가 있으면 표로 보여 주고 바꿀 항목만 묻는다. 없으면 2단계부터 한다.

## 2. 환경 점검

묻지 않고 확인해서 표로 보여 준다. 확인 못 한 것은 '미확인'.

| 항목 | 확인 방법 | 왜 필요한가 |
|---|---|---|
| OS | `uname` | crew 알림은 macOS에서만 소리와 함께 뜬다 |
| python3 | `python3 --version` | crew의 대기, 알림 스크립트 |
| git | `git --version` | 메이저 기능 커밋 |
| 기본 모델과 추론 강도 | Codex는 `~/.codex/config.toml`의 `model`, `model_reasoning_effort` | 설정과 다르면 알려 주기 위해. 세션을 `-m`으로 띄웠다면 그 값은 알 수 없다 |
| 멀티에이전트 기능 | Codex는 같은 파일 `[features]`의 `multi_agent` | 하위 에이전트를 쓸 수 있는지 |
| 설치된 묶음 스킬 | `~/.codex/skills/`, `~/.claude/skills/` | 빠진 스킬이 있으면 설치 안내 |

## 3. 질문

한 라운드에 다섯 개를 모두 묻는다. 질문마다 선택지와 추천을 붙이고, 사용자가 "전부 추천대로"라고 하면 그대로 저장한다. 보냈으면 턴을 끝내고 기다린다.

```
Q1. 이 스킬 묶음을 써 본 적이 있나요?
왜: 처음이면 확인 지점마다 무엇을 하면 되는지 한 줄씩 덧붙입니다.
  A. 처음  B. 몇 번 써 봤다  C. 익숙하다  D. 직접 입력
추천: A

Q2. 평소 어떤 입장에서 문제를 받나요? (과제마다 다시 확인하고, 이 답은 기본값으로만 씁니다)
왜: 내 문제면 나에게 직접 묻고, 현업 요건이면 현업에게 보낼 질문을 따로 만듭니다.
  A. 내 문제를 내가 푼다  B. 현업이 가진 요건을 받아 구현한다  C. 둘 다  D. 직접 입력
추천: C

Q3. 모델과 추론 강도는 어떻게 할까요?
왜: 스킬이 실행 중인 모델을 바꿀 수는 없습니다. 여기 값은 crew 세션 시작 명령과 하위 에이전트에 쓰고, config.toml 기본값이 다르면 알려 줍니다.
  A. config.toml 기본값 그대로 (<환경 점검에서 본 모델, 강도>)
  B. 계획과 검토는 높게, 구현은 기본으로
  C. 전부 가장 높게 (느리고 비쌈)
  D. 직접 입력 (모델 이름, 강도)
추천: B

Q4. 멀티에이전트를 허용하나요?
왜: 세션을 여러 개 띄우는 crew와, 커밋 검토를 하위 에이전트에 맡기는 것을 쓸지 정합니다.
  A. 세션 여러 개와 하위 에이전트 모두 허용 (동시 상한: <숫자>)
  B. 하위 에이전트만 허용
  C. 단일 세션만
  D. 직접 입력
추천: A (동시 상한 4)

Q5. 모든 작업에 공통으로 지킬 제약이 있나요? (여러 개 골라도 됩니다)
왜: 모든 계획의 금지 사항과 AGENTS.md에 들어갑니다.
  A. 따로 없음
  B. 외부 서비스로 데이터 전송 금지
  C. 패키지 설치는 확인 후에만
  D. 개인정보를 다룸 (로그, 테스트 데이터에 남기지 않음)
  E. 커밋은 되지만 푸시는 확인 후에만
  F. 직접 입력 (토큰/비용 상한, 쓰면 안 되는 도구 등)
추천: C, E
```

환경 점검에서 멀티에이전트 기능이 꺼져 있으면 Q4 선택지 옆에 그 사실을 적는다. 설치 안 된 묶음 스킬이 있으면 질문 전에 한 줄로 알린다.

## 4. 저장

`~/.screw-problem/설정.md`에 쓴다. 기존 파일이 있으면 먼저 읽고 바뀐 항목만 고친다.

```markdown
# screw-problem 설정

- 갱신: <YYYY-MM-DD>

## 사용자
| 항목 | 값 | 쓰이는 곳 |
|---|---|---|
| 사용 경험 | 처음 / 몇 번 / 익숙 | 설명 길이. 처음이면 확인 지점마다 할 일을 한 줄 덧붙임 |
| 평소 역할 | 내 문제 / 현업 요건 구현 / 둘 다 | 과제마다 역할을 물을 때의 기본값 |
| 모델: 계획과 검토 | <모델>, <강도> | problem-discovery, crew 킥오프와 노티, 커밋 검토 |
| 모델: 구현 | <모델>, <강도> | crew 작업 세션, 하위 에이전트 |
| 멀티에이전트 | 세션 여러 개 + 하위 에이전트 / 하위 에이전트만 / 단일 세션 | crew 제안 여부, 커밋 검토 위임 |
| 동시 상한 | <숫자> | crew 레인 수, 동시에 띄우는 하위 에이전트 수 |
| 공통 제약 | <목록> | 모든 계획의 금지 사항 |

## 환경 (<YYYY-MM-DD> 점검)
| OS | python3 | git | 기본 모델 | 멀티에이전트 기능 | 설치된 묶음 스킬 |
|---|---|---|---|---|---|
```

## 5. 마무리

- 저장한 설정을 한 표로 보여 준다.
- 다음에 할 일을 한 줄로: 처음이면 `$drill-pilot`으로 문제 이해부터, 익숙하면 `$problem-discovery`로 바로 계획.
- 설정은 `$screw-setup`으로 언제든 바꿀 수 있다고 알린다.

## 다른 스킬이 이 설정을 쓰는 방법

- 시작할 때 `~/.screw-problem/설정.md`를 읽는다. 없으면 `$screw-setup`을 먼저 하자고 한 줄로 제안하고, 사용자가 건너뛰면 기본값(추천 답)으로 진행하면서 '설정 없음'을 `사용자_검토.md`에 적는다.
- 사용 경험이 '처음'이면 확인 지점마다 사용자가 할 일을 한 줄 덧붙인다.
- 공통 제약은 계획의 금지 사항과 AGENTS.md에 그대로 옮긴다.
- 멀티에이전트가 '단일 세션'이면 crew를 제안하지 않고, 커밋 검토도 같은 세션에서 한다.
- 모델 설정은 crew 시작 지시문에 `codex -m <모델> -c model_reasoning_effort=<강도>` 형태로 넣는다. config.toml 기본값이 설정과 다르면 시작할 때 한 줄로 알리기만 하고 막지는 않는다.
