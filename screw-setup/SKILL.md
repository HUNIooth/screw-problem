# screw-setup

잘 안 바뀌는 설정을 한 번에 정한다. 과제마다 다른 것(이번 역할, 이번 제약)은 각 과제의 `HANDOFF.md`에서 정한다.

## 1. 점검 (묻지 않고 확인)

| 항목 | 확인 |
|---|---|
| OS, python3, git | `uname`, `python3 --version`, `git --version` |
| 모델, 추론 강도 | `~/.codex/config.toml`의 `model`, `model_reasoning_effort`. 세션을 `-m`으로 띄웠으면 미확인 |
| 하위 에이전트 | 지금 세션에 하위 에이전트 도구가 있는지 먼저, 보조로 `codex features list`의 `multi_agent`. config에 안 적혀 있다고 꺼진 것이 아니다 |
| 묶음 스킬 | 지금 로딩된 스킬 목록 먼저, 보조로 `~/.agents/skills`, `~/.codex/skills` |

- crew는 세션을 따로 여는 방식이라 하위 에이전트 기능이 없어도 쓸 수 있다.
- 기존 설정 파일이 있으면 보여 주고 바꿀 항목만 묻는다.

## 2. 질문 (한 번에 보내고 턴을 끝낸다)

```
Q1. 이 스킬 묶음을 써 본 적 있나요?  A. 처음  B. 몇 번  C. 익숙  D. 직접 입력   추천 A
Q2. 평소 입장은?  A. 내 문제를 푼다  B. 현업 요건을 구현한다  C. 둘 다  D. 직접 입력   추천 C
Q3. 모델과 추론 강도?  A. config 기본값(<점검값>)  B. 계획과 검토는 높게, 구현은 기본  C. 전부 최고  D. 직접 입력   추천 B
Q4. 멀티에이전트?  A. 세션 여러 개와 하위 에이전트(동시 상한 <n>)  B. 하위 에이전트만  C. 단일 세션  D. 직접 입력   추천 A, 상한 4
Q5. 모든 작업의 공통 제약? (여러 개)  A. 없음  B. 외부 전송 금지  C. 패키지 설치는 확인 후  D. 개인정보 다룸  E. 푸시는 확인 후  F. 직접 입력   추천 C, E
```

"전부 추천대로"면 그대로 저장한다.

## 3. 저장

`~/.screw-problem/설정.md`에 쓰고 저장됐는지 확인한다. 샌드박스나 권한 때문에 실패하면 승인을 요청하고, 그래도 안 되면 내용을 보여 주고 사용자가 저장하게 안내한다.

```markdown
# screw-problem 설정 (갱신 <YYYY-MM-DD>)
- 사용 경험:
- 평소 역할:
- 모델 계획과 검토: <모델>, <강도>
- 모델 구현: <모델>, <강도>
- 멀티에이전트: <값>, 동시 상한 <n>
- 공통 제약:
- 환경: <OS>, python3 <버전>, git <버전>, 하위 에이전트 <있음/없음/미확인>
```

마치면 저장한 값을 보여 주고 다음 할 일 한 줄: 처음이면 `$drill-pilot`, 익숙하면 `$when-you-encounter-problem`.

## 다른 스킬이 이 설정을 쓰는 법

- 시작할 때 읽는다. 없으면 `$screw-setup`을 한 줄로 권한다. 건너뛰면 권한이 걸린 것(멀티에이전트, 설치, 푸시, 외부 전송)은 허용하지 않은 것으로 두고 필요할 때 묻는다.
- 사용 경험이 '처음'이면 확인 지점마다 사용자가 할 일을 한 줄 덧붙인다.
- 공통 제약은 계획의 금지 사항과 AGENTS.md에 옮긴다.
- crew 시작 명령에는 `codex -m <모델> -c model_reasoning_effort=<강도>`로 넣는다.
