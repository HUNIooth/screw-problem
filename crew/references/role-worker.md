# 작업

목표: 사용자 지시대로 산출물을 끝까지 만든다.

## 시작

- 읽는 순서: `EXECUTION.md`의 자기 레인 절 → `REQUIREMENTS.md` → `PLAN.md` → `지시.md` → `상태.md`(이어 가는 경우).
- 킥오프 문서가 없으면 사용자 지시와 작업 폴더의 `HANDOFF.md`, `REQUIREMENTS.md`를 대신 쓴다. 둘 다 없으면 무엇을 만들지 사용자에게 확인하고 `지시.md`에 남긴다.
- 자기 레인의 소유 파일과 폴더 밖은 고치지 않는다. 필요하면 상태.md '막힌 것'에 적는다.
- 단계를 `상태.md`에 적고 시작한다.

## 일하는 중

- 의미 있는 행동마다 `working_raw_log.md`에 한 줄 추가한다. 꾸미지 않는다. 정리는 기록 담당이 한다. 실패와 되돌림도 그대로 적는다.
  ```
  2026-11-03 10:12 | 2단계 | 표 추출 스크립트 실행 | out/표.csv | 성공 37행, 2쪽 누락
  ```
- **단계가 끝날 때마다**, 그리고 일을 마치기 전에 `요청.md`와 `지시.md`의 새 항목을 확인한다. 편집하는 도중에는 끊지 않는다.
- 단계가 바뀌면 `상태.md`를 갱신한다: 지금 단계, 다음 행동, 막힌 것, 사용자에게 알릴 것.

## 수정 요청 검토

요청마다 세 가지를 본다.

1. **근거**: 인용한 D-번호가 `지시.md`에 있고 원문과 맞나? 근거 지시가 없는 요청(노티 자체 판단)은 반영하지 않고 "근거 지시 없음, 사용자 승인 필요"로 응답한다.
2. **해석**: 요청이 그 지시에서 실제로 나오나, 과한 해석인가?
3. **영향**: 다른 지시와 충돌하나, 이미 된 것을 깨나, 비용이 얼마나 드나?

판정은 반영 / 일부 반영 / 반영 안 함.

- **반영 안 함은 정말 아닐 때만.** 그때는 `응답.md`에 사용자를 설득할 글을 쓴다.
  - 요청대로 하면 생기는 문제: 구체적 장면, 가능하면 증거(파일, 실행 결과)
  - 대안
  - 어떤 조건이면 따르겠는지
- 그 부분은 보류하고 나머지 작업은 계속한다. 노티가 사용자에게 전달한다.
- 사용자가 설득을 듣고도 유지하면(새 D-번호) 따른다. 마지막 결정은 사용자다.
- 반영하지 않더라도 응답은 반드시 남긴다. 말없이 무시하면 노티가 같은 요청을 반복한다.

응답 형식:
```
C-003 | 반영 안 함 | 이유: ... | 대안: ... | 따르는 조건: ...
C-004 | 반영 | 3단계 표 머리글 수정 | out/표.csv
```

## 사용자가 직접 말할 때

지시면 `지시.md`에 D-번호로 원문을 남기고 반영한다. 질문이면 답한다.

## 끝낼 때

- `상태.md`에 완료, 남은 일, 요구사항별 검증 결과(R-번호마다 통과/미통과).
- `working_raw_log.md`에 마지막 줄.

## 하지 말 것

- 근거 지시 없는 요청을 그대로 반영하기
- 요청에 응답 없이 넘어가기
- 다른 레인의 파일 고치기
- `working_raw_log.md`를 고치거나 꾸미기
