# 작업

목표: 사용자 지시대로 산출물을 끝까지 만든다.

## 시작
- EXECUTION.md 자기 레인 → REQUIREMENTS → PLAN → 지시.md → 상태.md 순서로 읽는다.
- 킥오프 문서가 없으면 HANDOFF.md, REQUIREMENTS.md를 쓰고, 그것도 없으면 무엇을 만들지 확인해 지시.md에 남긴다.
- 소유 파일 밖은 고치지 않는다. 필요하면 상태.md '막힌 것'에 적는다.

## 일하는 중
- 의미 있는 행동마다 working_raw_log.md에 한 줄. 실패와 되돌림도 그대로.
- 단계가 바뀌면 상태.md를 갱신하고, 단계가 끝날 때마다 요청.md와 지시.md의 새 항목을 확인한다.
- 승인된 범위는 멈추지 않고 구현한다. 멈추는 곳은 둘이다.
  1. 커밋 분기점: 검토(`_crew/review/` 점검표), 무엇을 어떻게 짰는지, 질문, 커밋 메시지 초안을 상태.md에 쓴다. 지시.md에 컨펌이 오면 커밋한다.
  2. 기존 지시와 우선순위로 풀 수 없는 모호함이나 충돌: 그 부분만 멈추고 상태.md에 선택지와 추천을 쓴다. 답과 무관한 작업은 계속한다.
- 명확한 요구를 어긴 구현은 묻지 않고 고친다.
- 질문은 설계 선택과 놓쳤을 수 있는 것(설명과 다른 데이터, 규칙 없는 예외, 개인정보, 비용)을 합쳐 최대 3개. 넘치면 '대기 질문'. 결정은 선택지와 추천, 사실은 열어서.
- 기다릴 때: `wait_change.py --state _crew/.wait-<세션>.json --timeout 600 _crew/지시.md _crew/요청.md`, 읽은 뒤 `--done`.

## 작업 규칙
- 테스트 먼저, 통과 확인. 버그는 원인을 확인한 뒤 고치고, 같은 문제에서 두 번 실패하면 멈추고 올린다.
- 완료는 실행 결과를 상태.md에 붙여서만 말한다. 돌리지 않은 건 '미실행'.
- 요구사항에 없는 기능은 더하지 않는다.
- 마이너마다 다섯 줄 점검: 함수 하나는 한 가지 일 / 입출력, 업무 규칙, 저장을 섞지 않음 / 의존은 바깥에서 업무 규칙 쪽으로 / 비밀값은 코드 밖, 입력 검증, 쿼리는 매개변수 / 같은 코드 세 번 복사 금지.

## 수정 요청 검토
- 요청마다 본다: 근거(D 번호가 지시.md에 있고 원문과 맞나), 해석(과한가), 영향(다른 지시와 충돌, 이미 된 것을 깸, 비용).
- 근거 지시가 없으면 반영하지 않고 "근거 지시 없음, 사용자 승인 필요"로 답한다.
- 반영 안 함은 정말 아닐 때만. 응답.md에 요청대로 하면 생기는 문제와 증거, 대안, 따를 조건을 쓴다. 그 부분만 보류하고 나머지는 계속한다.
- 사용자가 그래도 유지하면 따른다. 응답은 반드시 남긴다.
