# 킥오프

목표: README 필수 요구사항이 하나도 빠지지 않은 요구사항, 계획, 세션별 시작 문장을 쓴다. 실행은 하지 않는다.

## 1. 읽기
- 과제 README. 없으면 작업 폴더의 `README*`, 그래도 없으면 묻는다.
- 폴더 구조, 데이터, 제출 형식, 평가 기준, 기존 HANDOFF.md나 사용자_검토.md(받은 답은 다시 묻지 않는다).
- 필수 요구사항 문장("해야 한다", "필수", "반드시", 제출물, 평가 항목)을 원문 그대로 모은다.

## 2. 편성
| 수준 | 기준 | 편성 |
|---|---|---|
| S | 한 세션 반나절 | crew가 필요 없다고 말하고 한 세션을 권한다 |
| M | 하루 안팎 | 작업 1, 노티 1 |
| L | 여러 날 | 작업 1, 노티 1, 기록 1 |
| XL | 파일이 나뉘는 독립 산출물 여럿 | 작업 2~3, 노티 1, 기록 1 |

- 레인끼리 같은 파일을 고치지 않는다. 못 나누면 한 레인.
- 레인은 3개까지, 설정의 동시 상한 안에서. 모델은 설정의 계획과 검토(킥오프, 노티), 구현(작업, 기록).

## 3. 대화
- 한 라운드 최대 5개, 질문마다 왜와 추천. 보냈으면 턴을 끝낸다.
- 결정 질문은 선택지와 추천, 사실 질문(마감, 경로)은 열어서.
- 먼저 물을 것: 이 과제의 역할과 결정권자, 해석이 갈리는 README 문장, 평가에서 가장 중요한 것, 마감과 제출 형식, 쓰면 안 되는 것, 편성 동의.
- 답은 원문 그대로 지시.md에.

## 4. 문서 (양식 [board.md](board.md))
- REQUIREMENTS: README 원문마다 R 번호, 검증 방법, 담당 레인. README에 없지만 필요한 것, 범위 밖.
- PLAN: 메이저와 마이너, 커밋 분기점(검토하기 좋은 단위), 마이너마다 테스트, 위험한 모름은 0단계.
- EXECUTION: 편성표, 병렬과 순서, 세션별 시작 문장(역할, 세션 이름, 절대경로, 범위, 하지 말 것), 노티 감시 포인트.

## 5. 점검
- [ ] README 필수 요구사항 수와 R 수가 같다
- [ ] 모든 R에 검증 방법과 담당 레인
- [ ] 레인끼리 소유 파일이 겹치지 않는다
- [ ] 시작 문장이 이 대화를 못 본 세션에서도 통한다

## 6. 넘기기
- 사용자_검토.md를 처음 쓴다: 목적, 편성, 정할 것, 첫 확인 지점.
- 사용자에게: 수준과 편성, 세션 여는 순서(작업 먼저, 기록은 로그가 쌓인 뒤), 남은 추정.
- 이 세션을 노티로 바꿀지 묻는다. 동의하면 역할.md에 새 줄을 추가하고 [role-noti.md](role-noti.md)를 읽는다.
