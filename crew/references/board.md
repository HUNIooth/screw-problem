# `_crew/` 파일 양식

처음 역할을 정한 세션이 `_crew/`를 만들 때 아래 머리말로 파일을 만든다. 킥오프 문서 3종은 킥오프가 쓴다.

---

## 역할.md

```markdown
# 세션 역할

| 세션 | 역할 | 범위 | 시작 | 상태 |
|---|---|---|---|---|
| S1 | 킥오프 → 노티 | 전체 | 2026-11-03 09:30 | 진행 중 |
```

## 사용자_검토.md

```markdown
# <과제명> 사용자 검토

사람은 이 한 장만 보면 됩니다. 자세한 경과: history.md

## 지금
- 단계: / 다음: / 막힌 것:

## 정할 것
- <질문, 선택지, 추천>

## 확인 지점 (최근 것이 위)
### <n>단계 끝, <시각>
- 한 일: / 볼 것: / 기준: / AI 추천:
- 내 결정 — 사용자 작성:
```

## 지시.md

```markdown

|---|---|---|---|---|
```

## REQUIREMENTS.md (킥오프)

```markdown
# <과제명> 요구사항

- 원천: <README 절대경로>
- README 필수 요구사항 원문 <n>개 → R <n>개

## README 필수 요구사항 추적
| R | README 원문 (그대로) | 해석 | 검증 방법 | 담당 레인 | 근거 |
|---|---|---|---|---|---|
| R-01 | "" | | | 작업-A | D-002 |

## 해석이 갈린 문장
| 문장 | 해석 1 | 해석 2 | 결정 | 근거 |
|---|---|---|---|---|

## README에 없지만 필요한 것
| R | 내용 | 이유 | 검증 방법 | 담당 |
|---|---|---|---|---|

## 범위 밖
-

## 제약
- 마감 / 제출 형식 / 제출 위치:
- 쓰면 안 되는 것:
```

## EXECUTION.md (킥오프)

````markdown
# <과제명> 실행 편성

- 문제 수준: L / 이유: <한 줄>
- 편성: 작업 1, 노티 1, 기록 1

## 편성
| 세션 | 역할 | 범위 | 소유 파일/폴더 | 담당 R | 시작 조건 |
|---|---|---|---|---|---|
| S1 | 노티 (킥오프에서 전환) | 전체 감시 | _crew/요청.md, 노티.md | 전체 | 지금 |
| S2 | 작업 | <범위> | <절대경로> | R-01~R-05 | 지금 |
| S3 | 기록 | history | _crew/history.md | - | 로그 30줄 이후 |

## 병렬과 순서
- 동시에: <단계들>
- 기다림: <단계>는 <단계>의 <산출물 경로>가 필요
- 합류: <단계>에서 <레인>이 통합, 통합 검증: <방법>

## 세션별 시작 지시문

### S2 작업
```
$crew 작업으로 시작한다.
작업 폴더: <절대경로>
<절대경로>/_crew/EXECUTION.md의 S2 범위만 맡는다. 소유: <경로>. 그 밖은 고치지 않는다.
REQUIREMENTS.md의 R-01~R-05를 모두 통과시키는 것이 목표다.
```

### S3 기록
```
$crew 기록으로 시작한다.
작업 폴더: <절대경로>
```

## 노티 감시 포인트
| R | 어긋남 신호 | 확인 방법 |
|---|---|---|

## 기록 정리 주기
- 로그 30줄마다 또는 단계 전환 때
````
