# 기록

목표: 사람이 `history.md`만 보고 **무엇을 했고, 무엇이 왜 바뀌었고, 지금 어디인지**를 1분 안에 안다.

## 입력

- `working_raw_log.md`: 무엇을 했나
- `지시.md`: 무엇을 시켰나
- `요청.md`, `응답.md`: 무엇이 왜 바뀌었나
- `노티.md`: 사용자가 무엇을 알았고 정했나
- `상태.md`: 지금 어디인가

원본은 읽기만 한다. raw log만 보면 "무엇을 했나"만 남는다. 지시와 요청, 응답을 같이 봐야 "왜 바뀌었나"가 남고, 나중에 가장 많이 찾는 게 그것이다.

## 언제 정리하나

- 길게 기다린다. 매 줄마다 정리하지 않는다.
  ```
  python3 <스킬 폴더>/scripts/wait_change.py --state _crew/.wait-기록.json --timeout 1800 \
    _crew/working_raw_log.md _crew/상태.md _crew/응답.md
  ```
- 새 로그가 30줄 넘게 쌓였거나, 상태.md에서 단계가 바뀌었거나, 응답.md에 반영 안 함이 생기면 정리한다. 그보다 적으면 다시 기다린다.
- 사용자가 "정리해"라고 하면 바로 한다.

## history.md

최신 날짜가 위로 온다.

```markdown
# <과제명> history

## 지금
- 단계: 3/5 표 검증
- 다음: 2쪽 누락 원인 확인
- 사용자 결정 대기: C-003 반론 (표 형식 유지 여부)

## 2026-11-03
### 한 일
- 10:12~10:40 표 추출 (out/표.csv, 37행). 2쪽 누락은 11:05 재추출로 해결
### 결정과 변경
- D-004 "머리글은 원문 그대로" → C-005 요청 → 반영 11:20
- C-006 반영 안 함 (이유: 원본 양식과 다름) → 사용자 유지 결정 D-007 → 반영 13:02
### 문제와 해결
- 같은 OCR 오류 3회 반복 → 노티 알림 → 쪽 단위 재처리로 해결

<!-- last: working_raw_log 412행, 응답 C-006 -->
```

- 한 줄에 한 사실. 같은 일의 로그 여러 줄은 하나로 묶고 시간 범위로 쓴다.
- 실패하고 되돌린 것은 결과만 남기고 원인은 한 구절로.
- 지시 번호, 요청 번호를 남겨 원본으로 거슬러 갈 수 있게 한다.
- 로그에 없는 이유는 짐작해 쓰지 않는다. "이유 기록 없음"으로 둔다.
- 맨 아래 주석에 마지막으로 정리한 위치를 남긴다.

## 하지 말 것

- 원본 로그 고치기
- 로그 줄을 그대로 옮겨 붙이기
- 작업이나 노티에 의견 내기 (필요하면 history의 '지금'에만 적는다)
