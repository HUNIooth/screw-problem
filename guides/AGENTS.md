# 파일과 작업 폴더 정리

## 시작할 때
- 작업 폴더를 확인하고 그 밖에는 쓰지 않는다. 다른 곳에 써야 하면 먼저 묻는다.
- 새 파일을 만들기 전에 폴더의 기존 구조와 이름 규칙을 본다. 규칙이 있으면 따른다.
- 같은 폴더에서 다른 세션이 작업 중일 수 있다. 포매터, 린터, 일괄 변경은 내가 만든 파일에만 돌린다.

## 어디에 두나
- 산출물: 사용자가 정한 위치. 없으면 작업 폴더 안 주제 폴더.
- 임시 파일(시험 스크립트, 중간 결과, 스크린샷, 로그): 작업 폴더가 아니라 `${TMPDIR:-/tmp}/codex/<작업명>/`. 끝나면 지운다.
- 홈 폴더, 바탕화면, 다운로드 폴더 맨 위에 파일을 흘리지 않는다.
- 도구가 만드는 부산물(`.playwright-*`, `__pycache__`, `.DS_Store`, 로그)은 임시 폴더로 보내거나 `.gitignore`에 넣는다.

## 이름
- 폴더 규칙이 없으면 `YYYYMMDD_내용` 또는 `내용_v2`. 공백 대신 `_`.
- `최종`, `final`, `진짜최종`, `복사본` 같은 이름을 쓰지 않는다. 확정본은 한 곳에 하나만 두고 나머지는 판 번호로 구분한다.
- 이름만 보고 내용을 알 수 있게 짓는다. `test.py`, `new.md`, `output.json` 같은 이름은 쓰지 않는다.

## 원본과 판
- 원본(받은 자료, 확정본, 사용자가 만든 파일)은 고치지 않는다. 고친 판은 새 파일로 만든다.
- 덮어쓰기 전에 대상을 열어 본다.
- 이전 판은 지우지 않고 `_이전/` 하위 폴더로 옮긴다. 작업 폴더 맨 위에는 현재 판만 둔다.
- 큰 파일(영상, 이미지 묶음, 데이터)은 복사하지 말고 경로로 참조한다.

## 지우기
- 이번 작업에서 내가 만든 파일만 지운다. 그 밖의 파일은 사용자에게 묻는다.
- `rm -rf` 대신 휴지통으로 보낸다(macOS `trash`).
- 폴더째 지우기 전에 안에 무엇이 있는지 목록을 본다.

## git 저장소에서
- 임시 파일, 부산물, 비밀값(`.env`, 키, 인증서)은 커밋하지 않는다. `git add` 전에 `git status`로 무엇이 들어가는지 본다.
- 커밋과 푸시는 요청받았을 때만 한다.

## 끝날 때
- 만든 파일, 바꾼 파일, 지운 파일을 경로와 함께 보고한다.
- 임시 폴더를 정리했는지 확인한다.
- 폴더에 작업 기록 파일(예: `CHANGELOG.md`, 작업 일지)이 있으면 오늘 한 일을 한 항목 추가한다.
