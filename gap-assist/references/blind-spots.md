# 빠지기 쉬운 곳

대상에 맞는 영역만 깊이 보고 나머지는 훑는다.

| 영역 | 점검 | 빠지면 | 흔한 선택지 |
|---|---|---|---|
| 목적과 효과 | 성공을 숫자로? 지금 값이 있나? | 끝나고 효과를 말할 수 없다 | 시간 절감 / 오류 감소 / 처리 건수 증가 |
| 범위 | 하지 않는 것, 대상 경계가 적혀 있나? | "이것도 되죠?"가 계속 붙는다 | 빈도 높은 유형 하나만 / 전체 지원, 예외는 수작업 |
| 입력 데이터 | 원천, 원본 여부, 형식, 받는 주기 | 실제 데이터에서 형식이 달라 멈춘다 | 정해진 양식만 / 변환 단계 / 다르면 사람에게 |
| 판단 기준과 정답 | 규칙 문장, 출처, 검증용 정답 사례 | 맞는지 아무도 판정 못 한다 | 과거 처리 건 / 2명 독립 판정 일치분 / 조항별 시험 사례 |
| 예외와 오류 | 규칙에 안 맞는 건, 깨진 입력, 중간 멈춤 | 한 건 때문에 전체가 멈추거나 조용히 틀린다 | 표시 후 사람에게 / 기본값 처리와 기록 / 중단과 알림 |
| 사람 확인 | 반드시 사람이 보는 지점과 담당 | 자동 결과가 그대로 나가거나, 전부 다시 봐서 효과가 없다 | 전 건 / 위험 건만 / 표본 |
| 권한, 보안, 개인정보 | 개인정보, 열람 범위, 외부 전송 | 다 만든 뒤 보안 검토에서 막힌다 | 마스킹 / 사내망 처리 / 보안 부서 사전 검토 |
| 규정과 내부통제 | 관련 규정, 처리 이력 보존 | 감사 때 근거를 못 댄다 | 판단마다 근거와 시각 기록 / 보관 기간 / 준법 확인 |
| 운영 | 누가 돌리고, 고장 나면 누구에게, 비용은 누가 | 담당자가 바뀌면 아무도 못 돌린다 | 시범까지만 / 현업 인수와 설명서 / 운영 부서 이관 |
| 변경 관리 | 규정, 양식이 바뀌면 무엇을 고치나 | 개정 후에도 옛 기준으로 판단한다 | 기준을 코드 밖 파일로 / 개정 시 재검증 / 판별 기준 보관 |
| 규모와 성능 | 많은 날 건수, 결과 기한 | 월말에 밀린다 | 실시간 / 매일 밤 일괄 / 요청 시 |
| 사용자와 전달 | 누가 어떤 형태로 받나 | 맞는데 아무도 안 쓴다 | 지금 양식 그대로 / 새 화면 / 메일 알림 |
| AI를 쓰는 경우 | 틀릴 때 알아채는 법, 근거 표시, 건당 비용 | 그럴듯하게 틀린 결과가 나가고 비용이 커진다 | 근거 인용 필수 / 정답 사례로 정기 재검증 / 비용 상한 |
