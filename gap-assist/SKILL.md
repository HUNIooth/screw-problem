# Gap Assist

목표: 빈 곳을 지적하는 데서 끝내지 않고 상대가 바로 정할 수 있게 한다.

## 순서

1. 대상(파일, 붙여 넣은 글)과 읽는 사람(현업 / 사용자 / 수행 에이전트, 모르면 사용자)을 정한다. 설정 파일이 있으면 사용 경험과 공통 제약을 따른다.
2. 대상이 하려는 일을 한 줄로 요약해 맨 앞에 둔다. 요약이 틀리면 사용자가 바로 고칠 수 있게.
3. [references/blind-spots.md](references/blind-spots.md)로 훑는다. 빈 곳은 없음 / 모호함("적절히", "필요시") / 충돌.
4. 확인으로 풀리는 건 직접 확인하고 출처를 단다. 사내 규정처럼 알 수 없는 건 '확인 필요(누구)'.
5. 치명(결과가 틀리거나 규정 위반)과 중요(나중에 고치면 비쌈)만 최대 7개. 참고는 끝에 한 줄씩.

## 형식

```
[치명] G1. <빈 곳 한 줄>
- 위치: <어디, 또는 없음>
- 왜 문제: <이대로 가면 생기는 장면>
- 선택지: A. <언제 맞나> / B. <언제 맞나> / C. <언제 맞나>
- 추천: <하나와 이유>
- 누가 정하나: <현업 / 사용자 / 확인 필요(부서)>
```

- 모를 법한 개념은 한두 줄로 먼저 푼다. 현업용이면 IT 용어를 쓰지 않는다.
- 선택지는 결과가 실제로 다른 것만. 진짜 2개뿐이면 2개.
- 근거 없는 "업계에서는 보통"은 쓰지 않는다. 일반론이면 일반론이라고 쓴다.

## 마무리

- 현업에게 그대로 보낼 질문 목록을 붙인다.
- 길면 대상 옆 `보완안내.md`, 짧으면 대화로. 짧게 쓴다: 개조식, 한 항목 한 줄.
- "반영해" 전에는 원문을 고치지 않는다. 반영할 땐 원본을 두고 새 판으로, 지적마다 고친 내용, 확인 결과, 남은 한계를 한 줄로 잇는다.
- 다음: 더 물어야 하면 `$drill`, 끝났으면 `$when-you-encounter-problem`. 마지막 줄은 상태줄.
